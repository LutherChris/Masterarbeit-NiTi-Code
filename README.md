# Description

This Python code is divided into five main modules.

| Module    | Usage                                                                |
| --------- | ---------------------------------------------------------------------|
| conv      | convergence tests for the scf-calculation                            |
| fermi     | plot of energy bands along high-symmetry lines in the Brillouin-zone |
| model     | calculation and modelling of bands and band-differences using `pw.x` |
| thz       | investigation of THz environments using `bands.x`                    |
| transport | calculation of transport properties using BoltzTrap2                 |

## Module conv

This module is used to perform the convergence of the self-consistency calculation of Quantum ESPRESSO (QE).
The total energy is calculated based on the following QE parameters:
- the parameter `ecutwfc`
- the parameter `nk` in K_POINTS automatic: (nk nk nk 1 1 1)
- the parameter `celldm(1)`
- the parameter `degauss` for various smearing methods and nk

The blocks are activated via main variables of the parameter-name.
The variation of the QE parameters is defined via lists.
When the program runs, the QE input file is modified for each list entry.
The QE calculation is then performed, and the converged total energy is extracted from the output file. The energies are saved as a CSV file in a conv_results subdirectory, alongside the list entries.
After the calculation, the respective convergence curve can be plotted with the variable plot=True. 
A definded convergence criterium is tested during the plot.

## Module fermi

In the band_x.in file of QE a path is defined along highly symmetrical axes.
This small module plots the band structure from a QE Gnuplot output-file; it does not calculate it.
The calculation is not initiated via Python.
First, the scf- and the nscf-calculation (pw.x and bands.x) must be performed manually via the terminal.
In the Python configuration-file of the module, the coordinate axes are adjusted according to this path.

## Module thz

This module calculates various paths per plane of the Brillouin zone using the QE subroutine `bands.x`.
The paths are generated by rotating an initial path within a plane perpendicular to a defined vector.

First, the number of data points per path and the angular increment of the rotation are defined.
An additional parameter specifies a displacement of the plane. This value can be varied using a list; subsequently, all paths within the plane are calculated for each value in this list.

The calculation proceeds in the following steps:
- First, the scf-calculation is performed if the QE `outdir` folder named `tmp_{prefix}` does not exist.
- Then, the contents of this folder are copied to a new folder named `tmp_{prefix}_COPY`.
- Next, the k-points in the QE input file are modified for the subsequent path.
- The band structure calculation is then performed using the `pw.x` program of QE.
- Subsequently, the `outdir` folder `tmp_{prefix}` is copied to a new folder `{prefix}_tmp`, where all band structure calculations for various paths are organized into subfolders.
- The folder containing the QE input files is also copied to a new folder named `{prefix}_out`.
- Upon completion of the calculation, the QE `outdir` folder `tmp_{prefix}` is cleared, and the SCF data is copied back to it from `tmp_{prefix}_COPY`. This ensures that the next band structure calculation starts from the same clean SCF calculation.

After the calculation has been performed, the XML files are read and the results are saved as CSV files.
The relevant bands are defined in the Python-code.
If exactly two bands are specified, the difference between them is also calculated.
In addition to the raw data, CSV files containing the local minima for each path are saved.
Once the calculations are complete, the data can be plotted.

## Module MODEL

This module is divided into `calc`, `use`, `plot`, and `path`.

In `calc`, the k-grid for calculations is defined and written to the QE input file in the
Card block K_POINTS {crystal_b}.
Various k-grids can be selected, for example, cartesian grids, cylindrical grids, or polar grids along a defined path.
Certain grid types can be specialized through Gaussian densification of the data points.
After that, the k-grid can be plotted.

Subsequently, the band energies and the squared magnitudes of the matrix impulse elements between valence and conduction bands can be calculated using QE.
The generated files are stored in a clear folder structure, and relevant information is extracted from the QE XML file.
The calculation initiates the following steps:
* If the SCF calculation has not yet been performed, it is executed using the QE input file located in the a `{prefix}` folder. The location of this folder is defined in a `config.py` file. (see tutorials below)
* Then, the SCF calculation data is copied from the `tmp_{prefix}` output directory to the `tmp_{prefix}_COPY` folder.
* Subsequently, the XML file from the SCF calculation is copied from the `tmp_prefix_COPY` folder to the `prefix_out/suffix/scf` folder. The name of the `suffix` subfolder is determined by the lattice definition specified earlier.
* Next, the k-points from the lattice definition are written into the QE input file for the NSCF calculation (located in the `prefix` folder).
* Then, the NSCF calculation is executed. This may take some time.
* Afterward, the NSCF calculation data is copied from the `tmp_prefix` output directory to the `prefix_tmp/suffix` folder. Additionally, all files from the configuration folder `prefix` are copied to `prefix_out/suffix`.
* Finally, the XML file from the NSCF calculation is copied from the `prefix_tmp/suffix` folder to `prefix_out/suffix/nscf`.
* Subsequently, all files in the `tmp_prefix` folder are deleted, and the SCF calculation from the `tmp_prefix_COPY` folder is copied into it. This ensures that the clean scf calculation is used for a re-run or for a calculation involving a different grid, without the need to recalculate it.

Once the band energies have been calculated, the squared magnitudes of the matrix elements of the momentum operator between the valence and conduction bands can be computed. The QE subroutine `bands.x` is used for this purpose.

Following the DFT calculation, the XML files from QE are read in during the analysis phase, and the relevant information is saved as a CSV file.
These calculations are written into the CSV file as new columns. Thus, the data from the QE calculation is not altered, but merely augmented or filtered.
If a calculation of matrix momentum elements was performed, the information from QE's `p_avg.dat` file is also read in, and the relevant data is saved.
Before modeling the band energies, coordinate transformations, PCA analysis, or data filtering to the THz-active region can be performed.

As long as the model function f(x, y, z) is linear in the coefficients λ, the problem can be written as an overdetermined system of equations Aλ=b, where b is the vector of the Energy-Data and A is a data matrix.
This system of equations is solved using NumPy's least-squares function.
To improve the conditioning of the system of equations, there is an option to perform column scaling on the data matrix A.
After modeling, the model is compared with the QE data points to estimate initial inaccuracies. The calculated model coefficients are saved as text files for later use.

# Tutorials

## Project Structure

The module-folders contain files in which the variables required for the calculations are defined. The module named `model` is an exception, as the configuration files are located in the subfolders 'fermi', 'model', 'thz', and 'transport'.

In the modules `model` and `thz`, there is a standard pattern for naming the configuration files:

| Configuration file with ...     | Usage         |
| ------------------------------- | --------------|
| `calc` in name                | calculation   |
| `plot` in name                | plotting      |

> Example 1\
> The file `nitiB2_conv_uspp.py` in the module-folder `conv` defines all variables for the scf-calculation and plotting.

> Example 2\
> The file `nitiB2_sect_uspp_point1_calc.py` in the sub folder `sect` defines all variables for the calculation of an bandstructure intersechtion.\
> The file `nitiB2_sect_uspp_point1_plot.py` defines variables for plotting.\

The `lib` subfolder of each module contains files in which functions and code sections are defined. Alongside these files, there is always a `config.py' file. This file must be manually configured before the first calculation.
Additionally, the configuration file `plot_config.py` defines global plot settings for the module. If a plot does not display correctly, the setting here must be adjusted. Alternatively, the specific plot function can be modified.

## Configuration of config.py

During the calculation process, Python will access various files and folders (and also create some). These files and folders are defined via the functions and variables in `config.py`.
Only three variables need to be defined manually:

| Variable         | Meaning                                             |
| ---------------- | --------------------------------------------------- |
| main_directory   | main folder path for calculations and results       |
| prefix           | subdirectory path for Quantum Espresso input-files  |
| num_cores        | number of cores for parallel calculations           |

A folder `pseudo` containing the pseudopotentials should be located in the main_directory folder.
The Quantum Espresso (QE) input-files are located inside the prefix-folder. Within these input-files, the QE-parameters are defined as the folder-names:
- prefix = 'prefix'
- pseudo_dir = '../pseudo'
- outdir = '../tmp_prefix'

> Example\
> The band structures of the B2 phase of NiTi are to be calculated using uspp-pseudopotentials. The main calculation directory is located at: `"/home/chris/nitiB2_uspp"`. The pseudo folder, containing the pseudopotentials is also located there. The `conv` module for the scf-calculation is used. Therefore, the subdirectory is named `nitiB2_conv`.\
> Consequently, the following variables in the Python-code are defined as:
>   - main_directory = "/home/chris/nitiB2_uspp"
>   - prefix = "nitiB2_conv"
>     
> Inside the QE-input-files, the QE-parameteres are defined as follows:
>   - prefix = 'nitiB2_conv'
>   - pseudo_dir = '../pseudo'
>   - outdir = '../tmp_nitiB2_conv'
